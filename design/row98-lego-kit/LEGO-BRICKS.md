# LEGO bricks — the true minimal list

**Status:** analysis for sign-off. No live file was edited. Formatting only; no IFRS wording is touched.

**What a brick is here:** one job a reader needs done (“tell me this is a group”, “tell me these must all hold”). It is *not* a CSS class. One brick can have many classes today; that spread is the problem `STANDARDISE.md` works on.

**Result:** **21 live bricks** in 8 families, plus **2 bricks to retire** (found in the files, banned by owner rules 8 and 9). Everything else on the 39 maps is one of these 21 under a chapter-local class name.

Picture of all 21: `lego-sheet.png`. One real crop per brick: `evidence/Bxx-*.png`.
Counts: `CENSUS.md` (generated by `tools/census.py` from the live files on this branch — dark theme, 1280 px, visible elements only; CF and IFRS 18 index maps scoped to `#conceptMap`).

“Section” below = the map’s own `aria-label` (or `fb-num`) for the place the brick sits.

## Why this list is minimal

- **Merged on reader job, not look.** 60+ title classes are one brick (B05). Spanning bar, bracket and shared-rule band are one brick (B13). Every `+ − = ± and or ‖` and ruled total line is one brick (B14) with variants.
- **Matrix, fork, ledger, timeline, statement are not bricks.** They are *components* built from bricks — see `LEGO-LOGIC.md`.
- **Kept apart on purpose:**
  - **Rail (B10) vs Kicker (B07)** — same job, different placement. The owner’s rules 2–3 are written for left rails, so the split must stay visible until a placement is chosen (STANDARDISE S1).
  - **Tone (B17) vs Strip (B18)** — Strip carries a specific signed meaning (FS line). Folding it into Tone is how it spread to traps and callouts.
  - **Axis (B15) vs Span (B16)** — rule 5 needs the between-marker note as its own thing; it is the missing piece today.
